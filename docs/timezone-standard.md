# 타임존 표준 (UTC/KST 하이브리드)

> 확정: 2026-06-16 (codex 상의 반영). 적용: **규약 확정 + 인프라 정렬 + 예약 도메인부터 신규 적용**(옵션 A).
> 핵심 원칙: **"전체 UTC / 전체 KST" 택1이 아니라, 값의 *의미*에 따라 저장 타입·타임존을 분리한다.**

## 1. 분류 규칙 (의미별 타입 매핑)

| 의미 | DB 타입 | Java 타입 | 타임존 | 예 |
|---|---|---|---|---|
| **발생 순간**(언제 일어났나) | `DATETIME(6)` | `Instant` / `OffsetDateTime` | **UTC** | 등록일시·수정일시·결제승인시각·환불시각·로그시각 |
| **비즈니스 날짜**(어느 날) | `DATE` | `LocalDate` | KST(로컬 날짜) | 체크인일·체크아웃일·요금일·재고일·정산기준일 |
| **시각만** | `TIME` | `LocalTime` | KST(로컬 시각) | 기본 체크인 15:00·체크아웃 11:00 |

### 왜 이렇게 나누나
- **발생 순간**은 "지구상의 한 순간"이라 UTC가 이식성·외부연동(결제/정산/로그)에 안전하고, 재사용 토대로서도 강하다.
- **숙박 날짜**(체크인/요금/재고)는 "순간"이 아니라 **한국 영업일/숙박일**이다. UTC 변환이 끼면 자정 경계에서 **하루 밀림 사고**가 난다. → 절대 timestamp로 저장하지 않는다.
  - 예: `2026-06-16T15:00:00Z`(UTC) = 한국 `2026-06-17 00:00`. 예약/요금/정산을 UTC datetime으로 처리하면 경계 사고.

## 2. 인프라 정렬 (전역 고정)

- **JVM**: `user.timezone=UTC` 고정 (배포 환경변수/실행 옵션).
- **JDBC**: `serverTimezone=UTC`.
- **발생 순간 생성**: SQL은 `NOW(6)` 금지 → **`UTC_TIMESTAMP(6)`** 사용 (커넥션 타임존 의존 제거 — 설정 실수에도 항상 UTC).
- **API 직렬화**: 발생 순간 값은 오프셋을 드러낸다 — `Instant`/`OffsetDateTime`로 `"2026-06-16T06:26:17Z"` 형태. 오프셋 없는 `LocalDateTime` 노출 지양.
- **화면 표시**: KST 변환은 **프론트 책임**(표준 응답은 UTC instant).

## 3. 금지 / 필수

- ❌ 숙박/요금/재고/정산 **날짜**를 `DATETIME`/timestamp로 저장 — 반드시 `DATE`(LocalDate).
- ❌ 발생 순간에 `NOW(6)` 신규 사용 — `UTC_TIMESTAMP(6)`.
- ❌ 발생 순간을 오프셋 없는 `LocalDateTime`으로 신규 API 노출.
- ✅ `DATETIME(6)` 컬럼은 "이 값은 **UTC instant**"라는 규약으로 통일(타입은 유지, 의미를 못 박는다).
- ✅ `TIMESTAMP` 타입 전환은 비권장(MySQL 세션 타임존 변환 개입) — `DATETIME(6)`에 UTC 명시가 더 예측 가능.

## 4. 적용 범위 / 전환 계획

| 대상 | 방침 |
|---|---|
| **인프라(JVM/JDBC)** | 즉시 정렬(UTC). 적용 시 dev DB는 재생성(기존 KST 저장값과 혼재 방지) — DB 영향 사전 보고 후 적용 |
| **신규 도메인(예약·요금·결제·정산)** | 처음부터 본 표준대로 — 날짜=DATE/LocalDate, 발생순간=UTC `DATETIME(6)`+`UTC_TIMESTAMP(6)`+Instant |
| **기존 4도메인(계정·인증·파일·문의)** | 발생순간 컬럼(REG_DT 등)은 인프라 정렬로 자동 UTC화. 응답 DTO의 `LocalDateTime`→`Instant` 정리는 **점진**(트래픽 없는 dev라 급하지 않음, 프론트 계약 변경 동반 시 공유문서 갱신) |

## 5. 프론트 계약 영향 (공유문서 갱신 필요 시점)

- 응답 시각 포맷이 `LocalDateTime`(`"...T15:26:17"`) → `Instant`(`"...T06:26:17Z"`)로 바뀌는 도메인은 `docs/share/frontend-api-guide`에 반영하고 공지한다.
- 날짜 필드(체크인 등)는 `"2026-06-16"`(date-only) 문자열로 계약.
