# ERD — '이음' 고택숙박 예약 (DB 스키마 설계) · v1.1 (codex 검토 반영)

> [domain-model.md](./domain-model.md) 기반 구체 스키마. MySQL8 / InnoDB / utf8mb4.
> 이 문서가 **Flyway 마이그레이션(V1…)의 원본**이 된다. (③ 단계에서 SQL로 변환 → 개발서버 적용)
> 현재 실제 적용 스키마(V1 + **V2 계정상세, 2026-06-11 적용**) 기준 정리는 [db-schema-current.md](./db-schema-current.md)를 본다.
> V2로 본 문서 A·B 영역(소셜/프로필/파트너/운영자/약관/파일/전화인증)이 구현됨 — 실제 명명·제약은 `V2__account_detail_terms_file.sql`이 우선.

> **명명 기준 주의**: 현재 V1 DDL은 [db-naming-standard.md](./db-naming-standard.md)의 공공데이터 공통표준용어 기반 명명으로 작성되었다.
> 예: `USER_ACCOUNT` → `USER_ACNT`, `COMMON_CODE` → `COMM_CD`, `PERMISSION` → `AUTH_MST`,
> `CREATED_AT/UPDATED_AT` → `REG_DT/MDFCN_DT`.
> 이 문서 본문에는 아직 개념 ERD용 영문 명칭이 일부 남아 있으므로, 실제 구현·검증 기준은 Flyway DDL과 `db-schema-current.md`를 우선한다.

> **v1.1 보강(codex ERD 검토)** — 핵심 리스크 3가지 대응: ① 예약/결제/환불/정산 **시점 스냅샷** 강화,
> ② 재고 **원장(transaction) 기반** 차감으로 동시예약 방지, ③ soft delete + **활성 유니크** 전략 명확화.
> 추가: 본인인증/전화/사업자검증/파트너승인/약관 **이력·스냅샷**, 정책 테이블(취소·환불·요금·성수기),
> 부분취소·환불/PG취소 분리, 쿠폰 대상/조건, 포인트 만료, **로그(Logging) 테이블군**, 조회 인덱스.

## 공통 규약
- 식별자: 테이블/컬럼 `UPPER_SNAKE_CASE`. 현재 V1 DDL의 surrogate PK는 공공 표준명 기준 `{엔터티}_SN BIGINT AUTO_INCREMENT`.
- 금액: **`BIGINT`(원 단위)**. 날짜시간: **`DATETIME(6)`** (KST 운영). 불리언: `CHAR(1)` `'Y'/'N'`.
- 문자셋: `utf8mb4` / `utf8mb4_0900_ai_ci`.
- **감사 컬럼(모든 업무 테이블 공통)**: `REG_DT DATETIME(6)`(등록일시), `RGTR_SN BIGINT`(등록자), `MDFCN_DT DATETIME(6)`(수정일시), `MDFR_SN BIGINT`(수정자), **`DEL_YN CHAR(1) DEFAULT 'N'`**(삭제여부). 삭제시각은 `MDFCN_DT`로 갈음.
- **모든 컬럼에 COMMENT(논리명) 필수.**
- **삭제 정책(D19)**: 즉시 물리삭제 금지. 삭제 = `UPDATE ... DEL_YN='Y', MDFCN_DT=now, MDFR_SN=actor` (soft delete, DB에 임시 보관).
  **유예기간(retention/grace) 경과분만 퇴거(purge) 배치로 물리삭제/익명화**(유예 판정 기준 = `MDFCN_DT`; `DATA_PURGE_LOG` 증적). 모든 조회는 `DEL_YN='N'` 필터 표준.
  - 유예기간 길이는 데이터 종류별 정책(개인정보는 큐어/법무, 예약·결제는 보존기간). 기본값은 정책 테이블/설정으로.
- soft delete + 활성 유니크: `DEL_YN`만으론 부족 → 활성행 전용 유니크는 **생성컬럼 `ACTIVE_KEY`**(예: `DEL_YN='N'`이면 원본값, 아니면 NULL) 기반 `UNIQUE`. (NULL 중복 허용 특성 이용)
- 코드성 값(상태/유형)은 가능한 `COMMON_CODE`로, 빈번·고정 상태는 컬럼+CHECK/주석.
- 인증주체(`USER_ACCOUNT`)와 도메인 PK 분리 원칙(D16) 유지.

아래 표기: `PK`=기본키, `FK`=외래키, `UK`=유니크, `IDX`=인덱스. **[S#]** = 도입 스프린트.

## A. 계정 / 인증 / 권한 [S1~S2]

> **계정 모델 원칙(D16 / codex 확정)** — "로그인 계정"과 "도메인 주체"를 분리한다.
> - **USER_ACCOUNT = 인증/로그인 계정**(`USER_ID`=account_id). 이메일/비번/상태/소셜식별 등 **인증 책임만**. 도메인 엔터티가 아니다.
> - **도메인 주체는 별도 PK + USER_ID(FK)**: `USER_PROFILE`(USER_PROFILE_ID), `PARTNER_BUSINESS`(PARTNER_ID), `MASTER_PROFILE`.
> - **모든 행위주체 참조는 `USER_ID`(account_id)를 FK**로 쓴다(예약자·작성자·승인자 등). 도메인 PK(PARTNER_ID 등)는 그 역할의 속성 묶음일 뿐.
> - 향후 SSO 분리 시 USER_ACCOUNT/소셜식별만 외부 IdP로 이관, 도메인 주체는 그대로 → `account_id`↔`sub` 매핑만 유지.

## v1.1 보강 — 규약 변경

- **활성 유니크 전략(확정 방향)**: soft delete와 충돌 방지. `EMAIL`, `CI`, `PHONE_NO`(USER_ACCOUNT), `BUSINESS_NO`(PARTNER), 소셜계정 등은
  **활성행 전용 유니크** = 생성컬럼 `ACTIVE_KEY`(예: `DEL_YN='N'`일 때 값, 아니면 NULL) 기반 `UNIQUE`. (NULL은 유니크 중복 허용)
- **숙박일은 `DATE`**(CHECKIN_DATE/CHECKOUT_DATE/STAY_DATE), 처리시각은 `DATETIME(6)`.
- **할인율은 `DECIMAL(5,2)`** 또는 bp 정수(금액은 `BIGINT` 원).
- **모든 FK 컬럼에 인덱스**. 모든 업무테이블에 감사컬럼(행 상태) + 별도 `AUDIT_LOG_INFO`(행위 추적) 병행.
- **핵심 상태(예약/결제/환불/정산)는 공통코드화하지 않고 enum성 코드 + 전이 규칙**으로 관리(상태머신 가드).

## I. 로그(Logging) 테이블군 [S1~]  ← 추가 요청 반영

> "행위/이력/외부호출"을 DB에 남겨 운영·분쟁·감사 대응. **애플리케이션 시스템 로그**(에러/디버그)는 DB가 아니라
> **파일+중앙수집(JSON+correlationId)** — D5/관측성 표준(decisions-pending §10). 아래는 DB에 남기는 로그.

| 테이블 | 용도 | 핵심 컬럼 |
|---|---|---|
| **AUDIT_LOG_INFO** | 행위 추적(개인정보 조회·CUD·권한변경) | ACTOR_ID, ACTOR_TYPE, ACTION, TARGET_TYPE, TARGET_ID, RESULT, IP, USER_AGENT, CORRELATION_ID, CREATED_AT |
| **LOGIN_HISTORY** | 로그인 시도/성공/실패 이력 | USER_ID NULL, LOGIN_ID, LOGIN_TYPE, RESULT(SUCCESS/FAIL), FAIL_REASON, IP, USER_AGENT, DEVICE, CREATED_AT |
| **EXTERNAL_CALL_LOG** | 외부연동 호출 로그(토스/포트원/알림톡/사업자검증/카카오맵) | PROVIDER, API, REQUEST_REF, REQUEST_PAYLOAD, RESPONSE_PAYLOAD(JSON), STATUS_CODE, SUCCESS_YN, ELAPSED_MS, CORRELATION_ID, CREATED_AT |
| **NOTIFICATION_DELIVERY** | 알림 발송 이력/재시도 | NOTIFICATION_ID FK, CHANNEL(ALIMTALK/PUSH/SMS/EMAIL), PROVIDER_MSG_ID, SEND_STATUS, FAIL_CODE, RETRY_COUNT, NEXT_RETRY_AT, SENT_AT |
| **FILE_ACCESS_LOG** | 비공개 파일 접근/다운로드 로그 | FILE_ID FK, ACTOR_ID, ACTION(VIEW/DOWNLOAD), IP, CREATED_AT |
| **MASTER_MFA_VERIFICATION_LOG** | 운영자 2차 인증 시도/결과 | USER_ID, METHOD, RESULT, IP, CREATED_AT |
| **DATA_PURGE_LOG** | 개인정보 파기 배치 증적 | TARGET_TYPE, TARGET_ID, PURGE_TYPE(MASK/DELETE), REASON, EXECUTED_AT |

> 로그성 테이블은 보존기간·파티셔닝(월별) 고려. 대용량은 적재 전용(인덱스 최소).
